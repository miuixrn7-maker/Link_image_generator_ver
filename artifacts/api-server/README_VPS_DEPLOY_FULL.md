## 1. Что нужно купить

### VPS-хостинг

**VPS (Virtual Private Server)** — это удалённый компьютер под Linux, который работает 24/7. Вы арендуете его у хостинг-провайдера и управляете через командную строку.

**Рекомендуемые провайдеры (с русским интерфейсом):**
- [Timeweb Cloud](https://timeweb.cloud) — просто и дёшево, хороший выбор для старта
- [REG.RU](https://reg.ru) — популярный российский хостинг
- [DigitalOcean](https://digitalocean.com) — международный, понятный интерфейс
- [Hetzner](https://hetzner.com) — европейский, хорошее соотношение цена/качество

**ОС:** выбирайте **Ubuntu 22.04 LTS** — самый распространённый и поддерживаемый вариант.

### Домен (необязательно)

Можно работать по IP-адресу VPS, но для постоянного использования удобнее домен вида `myphoto.example.com`. Домен покупается у любого регистратора отдельно.

## 2. Рекомендуемые характеристики VPS

Выбор конфигурации зависит от объёма обрабатываемых архивов:

| Конфигурация | CPU | RAM | Диск | Подходит для |
|---|---|---|---|---|
| Минимальная | 2 CPU | 2 ГБ | 40 ГБ NVMe | до 300 артикулов, ZIP до 1 ГБ |
| **Рекомендуемая** | **4 CPU** | **4 ГБ** | **80 ГБ NVMe** | до 700 артикулов, ZIP до 2 ГБ |
| Комфортная | 4 CPU | 8 ГБ | 160 ГБ NVMe | до 1200 артикулов, ZIP до 4 ГБ |

**Пороги нагрузки:**

```
🟢 Нормально (рекомендуемый VPS справится):
   до 500–700 изображений
   ZIP до 2 ГБ

🟡 Желательно делить архив на части:
   800–1200 изображений
   или ZIP 3 ГБ+

🔴 Обязательно делить — иначе OOM/timeout:
   1500+ изображений
   или ZIP 4–5 ГБ+
```

> **Важно:** диск NVMe быстрее обычного SSD при распаковке больших архивов. Не экономьте на дисковом пространстве — превью занимают много места.

## 3. Что вы получите после покупки

После оплаты и создания VPS провайдер пришлёт на почту или покажет в панели управления:

- **IP-адрес** — например `185.10.20.30`. Это адрес вашего сервера.
- **Логин** — обычно `root`
- **Пароль** — сгенерированный случайный пароль

> **Сохраните эти данные!** Они нужны для первого подключения.

## 4. Как подключиться к VPS

Подключение происходит по протоколу **SSH** — это зашифрованное соединение с удалённым сервером через командную строку.

### Windows

**Вариант 1 — Windows Terminal (рекомендуется, встроен в Windows 10/11):**

1. Откройте меню Пуск → найдите «Терминал» или «Windows Terminal»
2. Введите команду:

```
ssh root@185.10.20.30
```

*(замените `185.10.20.30` на ваш IP)*

3. При первом подключении появится вопрос — введите `yes`
4. Введите пароль (при вводе пароля символы не отображаются — это нормально)

**Вариант 2 — PuTTY (программа с графическим интерфейсом):**

1. Скачайте [PuTTY](https://putty.org)
2. В поле «Host Name» введите IP-адрес
3. Port: `22`, Connection type: `SSH`
4. Нажмите «Open»
5. Введите логин `root` и пароль

### Mac и Linux

Откройте «Терминал» и введите:

```bash
ssh root@185.10.20.30
```

После успешного подключения вы увидите приглашение командной строки вида:
```
root@vps-hostname:~#
```

## 5. Первичная настройка Ubuntu

Выполняйте команды по одной, дожидаясь завершения каждой.

### 5.1. Обновить список пакетов

```bash
apt update
```

> `apt` — менеджер пакетов Ubuntu. `update` — обновляет список доступных пакетов (не сами программы).

### 5.2. Установить обновления

```bash
apt upgrade -y
```

> `-y` — автоматически отвечает «да» на все вопросы. Процесс может занять 2–5 минут.

### 5.3. Установить необходимые пакеты

```bash
apt install -y git python3 python3-pip python3-venv nginx certbot python3-certbot-nginx
```

Это устанавливает:
- `git` — для скачивания проекта с GitHub
- `python3`, `python3-pip`, `python3-venv` — Python и его инструменты
- `nginx` — веб-сервер (будет работать как «посредник» перед нашим приложением)
- `certbot` — инструмент для получения бесплатного SSL-сертификата (HTTPS)

### 5.4. Создать пользователя для запуска приложения (рекомендуется)

Запускать приложение от имени `root` небезопасно. Создадим отдельного пользователя:

```bash
adduser deploy
```

Введите пароль, остальные поля можно оставить пустыми (нажимать Enter).

```bash
usermod -aG sudo deploy
```

> Добавляет пользователя `deploy` в группу `sudo` — для возможности выполнять команды с правами администратора.

## 7. Создание виртуального окружения Python

**Виртуальное окружение** — изолированная папка с пакетами Python только для этого проекта. Это позволяет избежать конфликтов с другими программами на сервере.

```bash
python3 -m venv venv
```

> Создаёт папку `venv/` внутри текущей директории.

Активируйте окружение:

```bash
source venv/bin/activate
```

После активации в начале строки появится `(venv)`:
```
(venv) deploy@vps:~/direct-links-generator/artifacts/api-server$
```

> **Важно:** при каждом новом SSH-подключении нужно снова активировать окружение командой выше. Systemd сделает это автоматически (см. раздел 12).

## 9. Создание файла .env

Файл `.env` содержит секретные настройки проекта (пароли, ключи). **Никогда не добавляйте его в GitHub.**

Создайте файл:

```bash
nano .env
```

> `nano` — простой текстовый редактор. Управление: `Ctrl+O` — сохранить, `Enter` — подтвердить имя, `Ctrl+X` — выйти.

Вставьте содержимое (замените значения на свои):

```env
ADMIN_LOGIN=admin
ADMIN_PASSWORD=ВашНадёжныйПароль123
SESSION_SECRET=случайная_строка_не_менее_32_символов_abcdef1234567890
BASE_URL=https://ваш-домен.ru
```

**Описание каждой переменной:**

| Переменная | Описание | Пример |
|---|---|---|
| `ADMIN_LOGIN` | Логин для входа в интерфейс | `admin` |
| `ADMIN_PASSWORD` | Пароль для входа. Используйте сложный! | `MyP@ss2024!` |
| `SESSION_SECRET` | Секретный ключ для шифрования сессий. Минимум 32 символа, случайная строка | `xK9mP2qR7vN4wL1eJ8tA5cF3hB6uD0sG` |
| `BASE_URL` | Публичный URL сайта без слеша в конце. Используется в CSV для формирования ссылок | `https://photos.myshop.ru` |

> **Генерация SESSION_SECRET:** выполните `python3 -c "import secrets; print(secrets.token_hex(32))"` и вставьте результат.

Сохраните файл: `Ctrl+O` → `Enter` → `Ctrl+X`.

## 10. Запуск проекта вручную (тест)

Перед настройкой автозапуска убедитесь, что приложение запускается:

```bash
source venv/bin/activate

```

**Что означают параметры:**
- `main:app` — модуль `main.py`, объект `app` (FastAPI-приложение)
- `--host 127.0.0.1` — слушать только локальный интерфейс (Nginx будет «проксировать» запросы)
- `--port 5000` — порт приложения

Вы должны увидеть:
```

```

Остановите тест: `Ctrl+C`.

## 12. Настройка systemd (автозапуск)

**Что такое systemd?**  
Это менеджер служб Linux. Он позволяет запускать приложение автоматически при старте сервера и перезапускать его при сбоях.

### 12.1. Создать файл службы

```bash
sudo nano /etc/systemd/system/directlinks.service
```

Вставьте содержимое:

```ini
[Unit]
Description=Генератор прямых ссылок
After=network.target

[Service]
User=deploy
WorkingDirectory=/home/deploy/direct-links-generator/artifacts/api-server
EnvironmentFile=/home/deploy/direct-links-generator/artifacts/api-server/.env
ExecStart=/home/deploy/direct-links-generator/artifacts/api-server/venv/bin/uvicorn main:app --host 127.0.0.1 --port 5000
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

> **Замените пути** если ваша папка проекта называется иначе.

Сохраните: `Ctrl+O` → `Enter` → `Ctrl+X`.

### 12.2. Применить и запустить службу

```bash
# Перечитать конфигурацию systemd
sudo systemctl daemon-reload

# Включить автозапуск при старте сервера
sudo systemctl enable directlinks

# Запустить прямо сейчас
sudo systemctl start directlinks
```

### 12.3. Проверить статус

```bash
sudo systemctl status directlinks
```

Должно быть: `Active: active (running)`.

### 12.4. Полезные команды для управления службой

```bash
# Остановить
sudo systemctl stop directlinks

# Перезапустить (после обновления кода)
sudo systemctl restart directlinks

# Просмотр логов (последние 50 строк)
sudo journalctl -u directlinks -n 50

# Следить за логами в реальном времени
sudo journalctl -u directlinks -f
```

## 13. Настройка Nginx (обратный прокси)

**Что такое Nginx и зачем он нужен?**  
Nginx принимает запросы от пользователей на порту 80 (HTTP) и 443 (HTTPS) и перенаправляет их на приложение (порт 5000). Это называется «обратный прокси».

Также Nginx позволяет:
- принимать большие ZIP-файлы (`client_max_body_size`)
- отдавать статические файлы быстрее
- подключить SSL (HTTPS)

### 13.1. Создать конфигурацию сайта

```bash
sudo nano /etc/nginx/sites-available/directlinks
```

Вставьте (замените `ваш-домен.ru` на ваш домен или оставьте `_` для работы по IP):

```nginx
server {
    listen 80;
    server_name ваш-домен.ru www.ваш-домен.ru;

    # Максимальный размер загружаемого файла (ZIP-архивы)
    # Увеличьте если загружаете архивы > 5 ГБ
    client_max_body_size 10G;

    # Таймаут для загрузки больших файлов (секунды)
    proxy_read_timeout 600;
    proxy_connect_timeout 600;
    proxy_send_timeout 600;

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Сохраните: `Ctrl+O` → `Enter` → `Ctrl+X`.

### 13.2. Активировать конфигурацию

```bash
# Создать символическую ссылку (активация сайта)
sudo ln -s /etc/nginx/sites-available/directlinks /etc/nginx/sites-enabled/

# Проверить конфигурацию на ошибки
sudo nginx -t

# Если всё ок — перезапустить Nginx
sudo systemctl reload nginx
```

### 13.3. Проверить

Откройте в браузере `http://185.10.20.30` — должна открыться страница входа.

## 14. Подключение домена

### 14.1. Купить домен

Купите домен у любого регистратора (RU-CENTER, nic.ru, reg.ru, namecheap.com и т.д.).

### 14.2. Добавить DNS-запись

В панели управления доменом добавьте A-запись:

| Тип | Имя | Значение | TTL |
|---|---|---|---|
| A | `@` | `185.10.20.30` (ваш IP) | 3600 |
| A | `www` | `185.10.20.30` (ваш IP) | 3600 |

Изменения DNS распространяются до 24 часов, обычно 15–60 минут.

### 14.3. Убедиться, что домен указывает на VPS

```bash
ping ваш-домен.ru
```

Должен показать ваш IP.

## 15. Включение HTTPS через Certbot

**HTTPS** — зашифрованное соединение. Обязательно, если вы работаете с паролями и загружаете файлы.

### 15.1. Получить сертификат

```bash
sudo certbot --nginx -d ваш-домен.ru -d www.ваш-домен.ru
```

Certbot:
1. Попросит email для уведомлений
2. Спросит про согласие с условиями → введите `A`
3. Спросит про рассылку → введите `N`
4. Автоматически изменит конфигурацию Nginx

### 15.2. Проверить

Откройте `https://ваш-домен.ru` — должен появиться замок в браузере.

### 15.3. Автообновление сертификата

Certbot добавляет автообновление автоматически. Проверьте:

```bash
sudo certbot renew --dry-run
```

Должно быть: `Congratulations, all simulated renewals succeeded`.

### 15.4. Обновить BASE_URL в .env

```bash
nano /home/deploy/direct-links-generator/artifacts/api-server/.env
```

Измените:
```
BASE_URL=https://ваш-домен.ru
```

Перезапустите службу:
```bash
sudo systemctl restart directlinks
```

```bash

# Windows (PowerShell)
scp deploy@185.10.20.30:~/direct-links-generator/backup_*.tar.gz .
```

## 18. Очистка VPS

### Встроенные инструменты очистки

В интерфейсе приложения на странице «История партий» есть три кнопки:

- **Очистить превью** — удаляет кэш миниатюр (~40–80% занятого места). Превью восстанавливаются автоматически при следующем открытии.
- **Очистить CSV** — удаляет готовые CSV-файлы. Можно пересоздать из интерфейса.
- **Очистить всё** — удаляет всё кроме настроек и метаданных.

### Команды очистки через SSH

```bash
# Проверить свободное место
df -h

# Посмотреть сколько занимают папки данных
du -sh ~/direct-links-generator/artifacts/api-server/data/*/

# Удалить только превью
rm -rf ~/direct-links-generator/artifacts/api-server/data/previews/*

# Удалить загруженные ZIP-архивы (уже не нужны после распаковки)
rm -rf ~/direct-links-generator/artifacts/api-server/data/uploads/*
```

> **⚠️ Осторожно с `rm -rf`!** Эта команда удаляет файлы без возможности восстановления.

## 19. Частые ошибки и решения

| Ошибка | Причина | Решение |
|---|---|---|
| `Port 5000 already in use` | Порт занят другим процессом | `sudo lsof -i :5000` → убить процесс: `sudo kill -9 <PID>` |
| `413 Request Entity Too Large` | Nginx отклоняет большой ZIP | Увеличьте `client_max_body_size` в конфиге Nginx (см. раздел 13) |
| `Permission denied` | Нет прав на файл/папку | `sudo chown -R deploy:deploy /path/to/folder` |
| `No space left on device` | Кончилось место на диске | Удалите превью через интерфейс или командой `rm -rf data/previews/*` |
| Превью не генерируются | Pillow не может открыть файл | Проверьте логи: `journalctl -u directlinks -n 50` |
| `BASE_URL incorrect` в CSV | Неверное значение BASE_URL в .env | Убедитесь что URL без слеша: `https://example.com` (не `https://example.com/`) |
| `Service failed to start` | Ошибка в конфигурации | `journalctl -u directlinks -n 100` — читайте последние строки с ERROR |
| `502 Bad Gateway` | Nginx не может достучаться до приложения | Служба не запущена: `systemctl start directlinks` |
| `Connection refused` при SSH | Неверный IP или порт | Проверьте IP в панели управления хостингом |
| Сайт открывается по IP, но не по домену | DNS не обновился | Подождите до 24 часов или проверьте A-запись у регистратора |

### Как читать логи при ошибке

```bash
# Последние 100 строк логов приложения
sudo journalctl -u directlinks -n 100 --no-pager

# Логи за сегодня
sudo journalctl -u directlinks --since today

# Логи Nginx
sudo tail -n 50 /var/log/nginx/error.log
```
