Project name:
“Генератор прямых ссылок”

Main goal:
Create an internal web app that processes ZIP archives with product images, lets the user preview and manually assign images, and generates a CSV file with direct public image URLs.

The app must be:

* simple
* stable
* fast
* practical
* optimized for real daily usage

UI language:
Russian.

Code, routes, variable names:
English.

Tech stack:

* Python
* FastAPI
* Jinja2 templates
* simple CSS or TailwindCSS
* JavaScript for frontend interactions
* Pillow for preview generation
* CSV export
* JSON metadata storage
* no database

Supported archive:
ZIP only.

If user uploads RAR:
show:

Main workflow:

1. User logs in.
2. User creates a new batch.
3. User enters batch name manually.
4. App appends current date automatically in format:
   batchname_DD-MM-YYYY
5. User uploads ZIP archive via drag-and-drop or file picker.
6. Upload progress is shown.
7. User can cancel upload.
8. If upload is slow or stalled, show:
   “Загрузка выполняется медленно”
   and buttons:
   “Повторить загрузку”
   “Отмена”
9. After upload show:
   “Распаковать архив”
   “Удалить архив”
10. User clicks “Распаковать архив”.
11. Show extraction progress/status in percent.
12. App extracts ZIP.
13. App recursively scans folders.
14. App detects articles.
15. App opens auto-distribution settings page.
16. User runs auto-distribution.
17. App opens preview page.
18. User manually fixes image assignment with drag-and-drop.
19. User generates CSV.
20. User downloads CSV.
21. User can delete batch.

Archive structure:
ZIP may contain many folders and subfolders.

Article detection rule:
The article is the last folder that directly contains supported image files.

Example:
Категория/
Подкатегория/
4664/
image1.jpg
image2.png

Article:
4664

Rules:

1. Scan ZIP recursively.
2. A folder becomes an article if it directly contains supported images.
3. Article name = folder name.
4. Parent folders are ignored for article naming.
5. File names may be anything.
6. Do not require filenames to match article.
7. Nested folders inside an article folder are allowed but should create a warning.
8. Unsupported files inside an article folder create an error but do not stop the whole batch.

Supported image formats:

* .jpg
* .jpeg
* .png
* .webp

System files:
Treat as warnings:

* .DS_Store
* Thumbs.db
* __MACOSX

Unsupported files:
If unsupported files are found inside an article folder:

* add error to article/file
* continue processing batch

Broken files:
Detect and handle:

* 0 byte files

Show errors:

Duplicate articles:

Duplicate filenames:

2. Rename following duplicates with suffix:
