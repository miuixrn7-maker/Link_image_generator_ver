2. DUPLICATE ARTICLE BEHAVIOR

Current required default behavior:
Duplicate articles must NOT be merged.

Example:
Категория_A/4664/photo1.jpg
Категория_B/4664/photo2.jpg

Both folders have article:
4664

Expected behavior:

1. Create two separate article entries.
2. Do not mix files from different folders.
3. Do not merge image lists.
4. Do not overwrite files.
5. Both visible article names remain:
   4664
6. Store source path for each article.
7. Show warning on each duplicated article:
   “Дубликат артикула — найдено несколько папок с таким названием”
8. Preview filter “Только с дубликатами” must show these articles.
9. CSV may contain duplicate rows in column:
   “Артикул”
10. CSV column “Путь” must distinguish duplicate article rows.

Internal implementation:
Use unique internal article ID to avoid collisions.

Suggested internal fields:

* article_id = article_name + "__" + short_hash_of_source_path
* display_article = article_name
* source_path = original parent folder path
* article_folder = original article folder path
* has_duplicates = true / false

UI display in Preview:
Show:

* Артикул: 4664
* Путь: Категория_A/

If duplicate:
show yellow warning:
“Дубликат артикула — найдено несколько папок с таким названием”

CSV:
Column “Артикул” should contain real article value:
4664

Column “Путь” should contain source path:
Категория_A/

If setting is “Считать ошибкой”:

1. Detect duplicate article names during extraction.

2. Stop before auto-distribution.

3. Do not open preview.

4. Show readable error:
   “В архиве найдены дубли артикулов. Переименуйте папки или измените настройку обработки дублей.”

5. List duplicated article names and paths.

6. Batch status should become:
   “ошибка”

7. Add detailed log entry.
